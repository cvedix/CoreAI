# CVEDIX Runtime SDK And Service Integration Plan

Ngày lập kế hoạch: 2026-06-24

## 1. Mục tiêu

Tài liệu này mô tả kế hoạch nâng cấp dự án CVEDIX Core từ một bộ node/sample nội bộ thành nền tảng có thể tích hợp vào nhiều dự án khác nhau.

Hướng phát triển đề xuất gồm hai lớp sản phẩm:

1. `cvedix_pipeline_api` hoặc `cvedix_runtime_sdk`: lớp SDK bọc node graph để ứng dụng C++/native tích hợp dễ hơn.
2. `cvedix-runtime-service`: service/container expose REST, gRPC, MQTT, RTMP/RTSP/WebRTC để tích hợp với hệ thống bên ngoài mà không cần link C++ trực tiếp.

Mục tiêu cuối cùng là giữ sức mạnh của kiến trúc node graph hiện tại, nhưng giảm độ phức tạp khi tích hợp, triển khai, debug và vận hành production.

## 2. Hiện trạng dự án

Dự án hiện được xây theo mô hình SDK core:

```text
samples
  -> cvedix_core
      -> nodes
      -> objects
      -> utils
      -> inference plugin backends
```

Các thành phần chính:

```text
nodes/        Node graph runtime: source, infer, track, OSD, destination, broker
objects/      Metadata objects: frame_meta, target, shapes, BA result
utils/        Logger, semaphore, plugin loader, analysis board, helper
third_party/  Backend/plugin and external libs: TensorRT, ONNX, OpenVINO, RKNN
samples/      Executable demos that manually compose node graphs
build/libs/   Shared libraries generated by CMake
build/bin/    Sample executables
```

Ví dụ pipeline hiện tại của `1-1-1_sample`:

```text
file_src_0
  -> yolo_detector_0
  -> bytetrack_0
  -> osd_0
  -> des_0_rtmp
```

Điểm mạnh hiện tại:

- Kiến trúc node graph linh hoạt.
- `cvedix_core` đã là shared library.
- Inference backend được tách thành plugin `.so`.
- Có nhiều loại source/destination: file, RTSP, RTMP, screen, web debug, broker.
- Có sẵn cơ chế queue, thread, metadata và hook.

Vấn đề cần cải thiện trước khi dùng như SDK/service cho nhiều dự án:

- Sample còn hardcode model path, video path, RTMP URL.
- Người tích hợp phải hiểu node graph nội bộ.
- CMake/install path còn phụ thuộc môi trường local.
- Plugin lookup phụ thuộc runtime library path.
- Chưa có public API facade ổn định.
- Chưa có runtime config chuẩn.
- Chưa có service API quản lý pipeline.
- Observability production còn thiếu metrics chuẩn.

## 3. Kiến trúc mục tiêu

Kiến trúc dài hạn:

```text
                    External Applications
                            |
       -------------------------------------------------
       |                                               |
 C++ Runtime SDK                                 Runtime Service
 cvedix_pipeline_api                       REST / gRPC / MQTT API
       |                                               |
       ---------------- cvedix_runtime -----------------
                            |
                        cvedix_core
                            |
       src -> infer -> track -> osd -> des/broker
                            |
       TensorRT / ONNX / OpenVINO / RKNN backend plugins
```

Nguyên tắc thiết kế:

- `cvedix_core` vẫn là engine node graph thấp tầng.
- `cvedix_pipeline_api` là API tích hợp C++ dễ dùng.
- `cvedix-runtime-service` là cách triển khai khuyến nghị cho khách hàng/team ngoài.
- Config pipeline phải dùng chung được giữa CLI, SDK và service.
- Backend plugin phải được quản lý bằng `plugin_dir`, không phụ thuộc ngẫu nhiên vào `LD_LIBRARY_PATH`.
- Runtime phải có metrics, healthcheck và logging rõ ràng.

## 4. Giai đoạn 1: Làm sạch core và packaging

### 4.1. Mục tiêu

Biến `cvedix_core` thành một thư viện có thể install, link và deploy ổn định.

### 4.2. Công việc

Chuẩn hóa CMake:

- Loại bỏ hardcoded path trong `CMakeLists.txt`.
- Chuyển các dependency local thành CMake option/cache variable.
- Đảm bảo `find_package(cvedix REQUIRED)` dùng được sau install.
- Tách `PUBLIC`, `PRIVATE`, `INTERFACE` dependencies rõ ràng.

Ví dụ mong muốn:

```cmake
find_package(cvedix REQUIRED)

add_executable(my_app main.cpp)
target_link_libraries(my_app PRIVATE cvedix::cvedix_core)
```

Chuẩn hóa thư mục install:

```text
/opt/cvedix/
  bin/
  lib/
  include/
  plugins/
  models/
  configs/
  share/
```

Chuẩn hóa runtime path:

```yaml
runtime:
  plugin_dir: /opt/cvedix/plugins
  model_dir: /opt/cvedix/models
  log_dir: /var/log/cvedix
  log_level: info
```

### 4.3. Kết quả đầu ra

- `libcvedix_core.so` install được.
- Header install sạch.
- Plugin backend install vào thư mục cố định.
- App khác có thể link bằng CMake package.
- Không còn hardcoded path theo máy developer.

## 5. Giai đoạn 2: Xây `cvedix_pipeline_api`

### 5.1. Mục tiêu

Ứng dụng tích hợp không cần tự tạo từng node như:

```cpp
file_src -> yolo_detector -> bytetrack -> osd -> rtmp_des
```

Thay vào đó chỉ cần truyền config và gọi API cấp cao.

### 5.2. API đề xuất

Header dự kiến:

```text
include/cvedix/runtime/pipeline.h
include/cvedix/runtime/pipeline_config.h
include/cvedix/runtime/runtime_context.h
include/cvedix/runtime/error.h
```

Ví dụ sử dụng:

```cpp
#include <cvedix/runtime/pipeline.h>

int main() {
    cvedix::PipelineConfig cfg;
    cfg.name = "traffic_yolo_rtmp";

    cfg.input.type = cvedix::InputType::File;
    cfg.input.uri = "/data/video.mp4";
    cfg.input.resize_width = 960;
    cfg.input.resize_height = 540;
    cfg.input.skip_interval = 3;
    cfg.input.play_at_realtime = true;

    cfg.model.type = cvedix::ModelType::Yolo;
    cfg.model.version = cvedix::YoloVersion::Yolo12;
    cfg.model.backend = cvedix::BackendType::TensorRT;
    cfg.model.model_path = "/models/yolo12n.engine";
    cfg.model.labels_path = "/models/coco.txt";
    cfg.model.conf_threshold = 0.30f;
    cfg.model.nms_threshold = 0.50f;

    cfg.tracker.enabled = true;
    cfg.tracker.type = cvedix::TrackerType::ByteTrack;

    cfg.osd.enabled = true;
    cfg.osd.show_bbox = true;
    cfg.osd.show_label = true;
    cfg.osd.show_track_id = false;

    cfg.output.type = cvedix::OutputType::Rtmp;
    cfg.output.uri = "rtmp://console.vinguard.cloud:1935/live/9000";
    cfg.output.encoder = "nvh264enc";
    cfg.output.bitrate_kbps = 2048;

    auto pipeline = cvedix::Pipeline::create(cfg);
    pipeline->start();
    pipeline->wait();
    pipeline->stop();
}
```

### 5.3. Class đề xuất

```text
cvedix::RuntimeContext
cvedix::Pipeline
cvedix::PipelineConfig
cvedix::PipelineFactory
cvedix::PipelineStats
cvedix::PipelineEvent
cvedix::Error
```

Trách nhiệm:

- `RuntimeContext`: quản lý plugin dir, model dir, logger, global runtime settings.
- `PipelineConfig`: mô tả input, model, track, OSD, output.
- `PipelineFactory`: dựng node graph từ config.
- `Pipeline`: start, stop, pause, resume, wait, get stats.
- `PipelineStats`: FPS, latency, queue, dropped frames.
- `PipelineEvent`: detection event, lifecycle event, error event.

### 5.4. API lifecycle

```cpp
class Pipeline {
public:
    static std::unique_ptr<Pipeline> create(const PipelineConfig& config);

    bool start();
    bool stop();
    bool pause();
    bool resume();
    bool wait();

    PipelineStats stats() const;
    PipelineState state() const;

    void set_event_callback(EventCallback cb);
    void set_error_callback(ErrorCallback cb);
};
```

### 5.5. Kết quả đầu ra

- App C++ chỉ cần 10-30 dòng để chạy pipeline.
- Không phải trực tiếp thao tác `attach_to()`.
- Node graph vẫn còn available cho advanced users.

Ưu tiên thực tế:

1. Xây `cvedix_pipeline_api`.

## 13. Rủi ro kỹ thuật

### 13.1. ABI C++

Nếu app khác link trực tiếp C++ SDK, ABI có thể vỡ do khác compiler, libstdc++, OpenCV hoặc TensorRT.

Giảm rủi ro:

- Cung cấp Docker image chính thức.
- Cung cấp C API wrapper.
- Version hóa dependency.

### 13.2. Plugin loading

Backend được load bằng `.so`; nếu path sai sẽ fail runtime.

Giảm rủi ro:

- Có `plugin_dir`.
- Validate plugin trước khi start pipeline.
- Log rõ plugin nào được load.

### 13.3. Dependency nặng

TensorRT, OpenCV, GStreamer, FFmpeg, Kafka, MQTT làm deploy phức tạp.

Giảm rủi ro:

- Container hóa.
- Chia image theo backend: CPU, TensorRT, RKNN.
- Tách optional feature bằng CMake option.

### 13.4. Lifecycle node graph

Mỗi node có thread và queue riêng. Nếu API public để người dùng tự ghép node, dễ gặp lỗi lifecycle.

Giảm rủi ro:

- Bọc bằng `Pipeline`.
- Chỉ expose advanced node graph API cho nội bộ.

- Có thể chạy bằng CLI `cvedix-runtime --config`.
- Có Docker image chạy được trên GPU TensorRT.
- Có REST healthcheck.
- Có metrics FPS/latency/drop cơ bản.
- Không cần sửa source code khi đổi video/model/RTMP URL.

## 16. Kết luận

Hướng phát triển phù hợp nhất là:

```text
cvedix_core
  -> cvedix_pipeline_api
  -> config-driven runtime
  -> service/container
  -> public SDK
```

Cách này giữ được kiến trúc node graph hiện tại, đồng thời tạo lớp tích hợp đủ sạch cho nhiều dự án khác nhau. Với khách hàng hoặc team ngoài, service/container nên là hướng ưu tiên trước SDK public, vì dễ deploy, dễ kiểm soát dependency và ít rủi ro ABI hơn.
